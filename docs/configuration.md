# Application configuration and test isolation

The reel reads `%LOCALAPPDATA%\CopilotReel\apps.ini` by default. Choose the main wheel's **+** entry to open the combined hub; use its grid icon to manage 1-8 targets or its + icon to add. Existing targets, app actions, and the preset collection use nested wheels. Text and launch details open a focused native editor. Each entry requires a name and actual target; a preset whose application is not found opens the editor to request its local application rather than substituting a website.

In the editor, **Choose app…** beside the target lists the applications in Start's All apps (`shell:AppsFolder`) with their Start icons, sorted by name, and a search box filters them by every typed word. Choosing one (double-click, Enter or **Choose**) replaces the entry's name and launch fields, and **Save** stores it: a packaged app as its AUMID, a desktop app as its Start shortcut's executable with the shortcut's arguments. Both are local applications, so a short tap opens them. Only such applications are listed: websites, documents, MMC consoles, shell locations such as File Explorer and Control Panel, uninstallers and shortcuts whose executable is missing are left out. **Browse…** still picks any `.exe`, `.lnk` or `.url` file, and the target stays editable by hand. The list is read on a worker thread the first time the page opens in an editor window.

**Add** first lists the apps taken out of the reel, most recent first; one tap puts one back exactly as it was saved, with its name, target, arguments and working directory. The agents discovered on this computer that are not in the reel yet follow, in catalog order; one tap saves the discovered launch target (the executable, or the package's AUMID). Catalog entries that still need a target follow, then **Custom app**. Two targets that launch the same application, such as two shortcuts to one executable, count as one, and a discovered agent that a parked app already offers is listed once.

To change the order, open **Manage apps** and drag an app's tile: once the pointer moves past the Windows drag threshold the tile lifts and follows it, and the other apps slide along the orbit to open the slot nearest the pointer. Releasing there saves the new order at once; releasing on the tile's own slot, pressing **Esc** or right-clicking puts it back. With an app selected, **A / D** move it one place earlier or later. The preferred agent stays the same app. A press that does not move is a click and opens the app's actions.

While a tile is lifted the center shows a red trash. Releasing the tile on it (inside the center zone) takes the app out of the reel, as do **Delete** on a selected app and **Remove from reel** on its actions page. The app is not deleted: its settings move to `parked.ini` beside `apps.ini` (the same format under `[CopilotReelParked]`, at most 16 apps, most recent first), and **Add** offers it first. The last app cannot be taken out; the trash is drawn disabled. When the preferred agent is taken out, the first remaining app becomes preferred, so putting the old one back later does not take the short tap over again. A damaged `parked.ini` is left in place and ignored; it never blocks the reel. Supported launch methods are Shell (an executable, shortcut, or URI) and an installed application's AUMID. Shell entries can also specify arguments and a working directory.

Application configuration uses UTF-16 LE with a BOM and preserves Unicode text. Backslashes are escaped as `\\`; tabs are escaped as `\t`. Quotes and equals signs do not need escaping. The schema version is `Version=1`. Prefer the settings window over manual editing. Saving writes a temporary file in the same directory, flushes it, and then replaces the configuration. When loading detects corruption, it retains the original file and temporarily supplies the default entries.

## Interface language

English is the default interface language. Open **Main reel > +**, then click the small arrows flanking the **EN/ZH** tile, or press **A / D**, to switch between English and Simplified Chinese. This is an in-place radial adjustment, not a dropdown in a separate rectangular settings window. The change updates the EN/ZH icon, tray text, editor labels, and subsequent dialogs. Hovering the EN/ZH tile or either arrow shows Language at the center. No fixed language heading, caption beneath the tile, or keyboard hint is rendered inside the wheel. Stored entry names remain user data. Built-in Notepad and Windows Settings labels, including the legacy Chinese defaults, are localized only while drawing the UI; their stored names and launch identities are untouched. Explicit custom names remain unchanged. The packaged app starts in the background at sign-in through a startup task; turn it off under Windows **Settings > Apps > Startup**. Removing and reinstalling the package turns it back on; `tools/install-development.ps1` records the state before the reinstall and turns the task off again when it was off. Choosing Copilot Reel in Start while it runs opens the click-to-select preview. While it is not running, Windows starts it the same way for Start and for the Copilot key; the reel opens the preview when Start or search was in front, and otherwise treats the start as a key tap that opens the preferred agent. The tray icon and `Ctrl+Alt+R` always open the preview.

Language preference is stored independently in `%LOCALAPPDATA%\CopilotReel\preferences.ini`:

```ini
[General]
Language=en-US
ReelSize=100
```

Both languages read the same `apps.ini` and `behavior.ini` in the active profile. Switching language writes only `preferences.ini`; it never selects another application list, icon set, target order, or preferred target. The installed MSIX and a standalone development executable may have separate Windows application-data scopes. That distinction is packaging, not language. Isolated tests explicitly override their scope with `COPILOT_REEL_DATA_DIR`. Diagnostics expose the active `dataPath` and `language`.

The supported persisted values are `en-US` and `zh-CN`. Missing or invalid values select English. The radial adjustment applies only after its atomic preference write succeeds. The command-only wheel disables IME composition so A/D work under a Chinese keyboard layout; native text editors keep their input method. Windows-owned dialog controls may follow the Windows display language.

## Reel size

Open **Main reel > +** and choose **Reel size** to step the reel through 70%, 85%, 100% and 115%; after 115% it returns to 70%. The tile shows the current step itself. 100% is the 0.8 scale the reel always used. The open reel resizes in place around the point it opened at: at a screen edge it moves inward only as far as the new size needs, and on a small work area the whole canvas shrinks to fit, exactly as when it opens, so no part of it leaves the work area. The step is stored as `ReelSize` beside the language in `preferences.ini` (`ReelSize=85`); a missing or unknown value selects 100%, and saving either preference keeps the other. Diagnostics expose `reelSize`. The native editor window keeps its size.

## Preferred agent

Open **Main reel > + > Manage apps**, choose an app and choose **Set as preferred**; the reel returns to **Manage apps** with the preferred badge on that app. While the reel is closed, a short Copilot tap launches the preferred local application; a hold opens the reel. Inside an open menu a tap confirms the selected item instead. If the preferred application is a packaged app, an absolute executable or a shortcut to one and is already running, its window comes forward instead of a second start. An entry with arguments or a working directory, a shortcut that carries arguments, a bare name such as `notepad.exe` and a URI such as `ms-settings:` are always started. The preferred marker appears on the selected agent's tile. `behavior.ini` stores a versioned hash of launch kind, target, arguments, and working directory, independently of the language file. Renaming and reordering retain the preference; taking the preferred profile out of the reel makes the first remaining entry preferred, and an edit elsewhere that removes it falls back to the first entry.

Fresh defaults use up to six discovered installed native applications, followed by Notepad and Windows Settings. Only known ChatGPT and Claude base-URL default profiles can migrate automatically to their verified installed target; the configuration is backed up before that migration is saved. Arbitrary pages and custom URLs are not migrated. User-created web targets remain usable through an explicit wheel selection, but short tap does not launch HTTP/HTTPS destinations. If a preferred web entry cannot resolve to an installed local application, a native picker titled Choose a local application requests an `.exe` or `.lnk` file. Selecting a web entry as preferred uses the same picker. A successful choice replaces the selected launch profile; a short tap then opens that local target. Missing presets still use the focused editor for name and target details. Cancelling does not open a browser.

The shared localization API in `src/localization.h` provides `CurrentLanguage`, `SetLanguage`, `Tr`, `LoadLanguage`, and `SaveLanguage`. Call `LoadLanguage` once during startup. It sets the current language and returns it. `SaveLanguage` stores the supplied preference without changing the current session language. Source comments, identifiers, diagnostic details, configuration keys, and development documentation use English; product UI translations are explicit string pairs.

## Isolated test data

Set `COPILOT_REEL_DATA_DIR` only in the test process environment to override the directory containing `apps.ini`, `parked.ini`, `preferences.ini`, and `behavior.ini`. The value must be an absolute drive path, such as `C:\dev\copilot-reel\build\test-data`, or a complete UNC share path. Relative paths, drive-relative paths such as `C:temp`, and device namespaces are rejected. An invalid override never falls back to the current working directory or the user's real configuration. An unset or empty override uses the normal LocalAppData location.

Create a dedicated directory before starting the test process. Do not persist this variable through system environment settings, and do not point it at existing user configuration. An already-running single instance keeps its startup environment; launch the target instance itself with the isolated environment.

`tests/launch_probe.cpp` builds as a separate Windows-subsystem executable with a `wWinMain` entrypoint. It has no window and launches no other application. Each invocation appends one `launched` line to `launch-probe.txt` in the explicitly supplied test directory, allowing duplicate launches to be detected. Missing environment variables, invalid paths, or missing directories cause a nonzero exit without writing to the default configuration location.

`tests/settings_tests.cpp` tests parsing, escaping, and validation boundaries of `apps.ini` and `parked.ini` without reading or writing the user's configuration or invoking window APIs; the atomic writer is exercised only in a private temporary directory. Its Unicode fixture data intentionally includes non-English names and paths.
